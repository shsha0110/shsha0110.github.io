들어가며 (Introduction)

딥러닝 모델을 학습한다는 것은 결국 손실 함수 \(\ell(\theta)\)를 최소화하는 파라미터 \(\theta\)를 찾는 최적화(optimization) 문제를 푸는 일입니다. 우리는 이미 역전파(backpropagation)를 통해 임의의 파라미터 지점에서 그래디언트 \(\nabla \ell(\theta)\)를 계산하는 방법을 알고 있습니다. 이제 남은 질문은 다음과 같습니다.

“계산한 그래디언트를 가지고, 파라미터를 구체적으로 어떻게 갱신(update) 할 것인가?”

이 갱신 규칙(update rule)을 정의하는 객체가 바로 옵티마이저(optimizer) 입니다. 이번 실습에서는 PyTorch가 제공하는 torch.optim을 그대로 쓰는 대신, 옵티마이저를 밑바닥부터 직접 구현하면서 다음을 학습합니다.

  • 여러 옵티마이저가 공유하는 공통 인터페이스를 추상 클래스로 추출하는 객체지향 설계
  • SGD → Momentum → RMSProp → Adam 으로 이어지는 갱신 규칙의 발전 과정과 각 단계의 동기(motivation)
  • 직접 만든 옵티마이저로 Transformer 언어 모델을 실제로 학습시키고 성능을 비교하기

전체 흐름은 “왜 이전 방법으로는 부족한가 → 그래서 무엇을 추가하는가”라는 한 줄기 서사로 이어집니다. 각 옵티마이저의 한계가 다음 옵티마이저를 낳는 구조이므로, 순서대로 따라오시길 권합니다.

1. 추상 옵티마이저 클래스 (Abstracted optimizer class)

1.1. 왜 추상 클래스가 필요한가

우리가 다룰 SGD, Momentum, RMSProp, Adam은 갱신 규칙(update_dict)만 서로 다를 뿐, 그 외의 동작은 거의 동일합니다.

  • 모델의 모든 파라미터를 딕셔너리 형태로 가지고 있어야 하고,
  • 매 스텝마다 파라미터에서 갱신량을 빼주어야 하며,
  • 가중치 감쇠(weight decay) 같은 정규화 처리를 동일하게 적용해야 합니다.

이렇게 공통된 골격은 부모 클래스에 두고, 달라지는 부분만 자식 클래스에서 재정의하는 것이 객체지향 설계의 핵심입니다. 따라서 우리는 공통 로직을 담은 추상 클래스 Optimizer를 먼저 정의하고, 구체적인 옵티마이저들은 이를 상속받아 update_dict 메서드만 구현하는 방식을 택합니다.

1.2. 사전 약속: Module 인터페이스

이번 실습의 신경망은 직접 구현한 Module 클래스의 인스턴스로 주어지며, 옵티마이저는 이 인터페이스와 호환되어야 합니다. 우리가 사용할 핵심 메서드는 다음 두 가지입니다.

  • .state_dict() : 모듈의 모든 파라미터를 딕셔너리 형태로 반환합니다. 반환된 딕셔너리의 값을 수정하면 모델 자체의 파라미터가 갱신됩니다(참조를 공유하므로). 옵티마이저가 파라미터를 직접 손볼 수 있는 통로입니다.
  • .grad_dict() : 각 파라미터에 대응하는 그래디언트를 동일한 키 구조의 딕셔너리로 반환합니다.

여기에 더해, 중첩된 딕셔너리를 평탄화(flatten)해 다루기 쉽게 만들어 주는 유틸리티 unfold_dict를 사용합니다. 덕분에 옵티마이저는 파라미터의 구체적인 계층 구조를 신경 쓰지 않고, 단일 키-값 딕셔너리로 모든 파라미터를 일괄 처리할 수 있습니다.

1.3. 가중치 감쇠 (Weight decay)의 수식 유도

추상 클래스에는 정규화를 위한 wd_grad 메서드가 포함됩니다. 과적합(overfitting)을 막기 위해 학습 손실에 \(L_2\) 패널티 항을 더하는 것이 일반적입니다.

\[ \ell'(\theta) = \ell(\theta) + \frac{1}{2}\gamma \|\theta\|^2 \]

여기서 \(\gamma\)는 가중치 감쇠 계수(코드의 wd)입니다. 실제 갱신에 필요한 것은 손실 자체가 아니라 그 그래디언트이므로, 패널티 항을 미분해 봅니다. \(\|\theta\|^2 = \theta^\top \theta = \sum_i \theta_i^2\) 이므로

\[ \frac{\partial}{\partial \theta_i}\left(\frac{1}{2}\gamma \sum_j \theta_j^2\right) = \frac{1}{2}\gamma \cdot 2\theta_i = \gamma \theta_i \]

벡터 형태로 쓰면 다음과 같습니다.

\[ \nabla \ell'(\theta) = \nabla \ell(\theta) + \gamma\, \theta \]

직관 보충. 계수 \(\frac{1}{2}\)을 붙여 둔 이유가 여기서 드러납니다. 제곱 항을 미분하면 2가 내려오는데, 이 2와 \(\frac{1}{2}\)이 상쇄되어 깔끔하게 \(\gamma\theta\)만 남습니다. 결국 가중치 감쇠는 매 스텝 그래디언트에 현재 파라미터에 비례하는 항을 더해, 파라미터를 항상 원점(\(0\)) 쪽으로 조금씩 끌어당기는 효과를 줍니다. 이는 가중치가 과도하게 커지는 것을 억제해 일반화 성능을 돕습니다.

따라서 wd_grad는 입력으로 받은 그래디언트 딕셔너리의 각 항에 \(\gamma\theta\)를 더해 반환하면 됩니다.

1.4. 코드 구현

import torch
from util import unfold_dict

class Optimizer():
    def __init__(self, model, wd=0.0001, **kwargs):
        self.model = model
        self.param_dict = unfold_dict(self.model.state_dict())
        self.wd = wd

    def step(self):
        # 갱신량의 norm. 보통 clipping이나 로깅에 쓰이나 여기선 사용하지 않음.
        grad_norm = 0

        step_dict = self.update_dict()
        for k in self.param_dict.keys():
            self.param_dict[k] -= step_dict[k]
            grad_norm += (step_dict[k].abs()).sum()

        return grad_norm

    def wd_grad(self, grad_dict):
        for k in grad_dict.keys():
            grad_dict[k] += self.wd * self.param_dict[k]

        return grad_dict

    def update_dict(self):
        """
        갱신 규칙을 정의하려면 이 함수를 구현해야 함.
        """

설계의 핵심을 정리하면 다음과 같습니다.

  • step() : 모든 옵티마이저가 공유하는 실제 갱신 루프입니다. update_dict()가 반환한 갱신량(step) 을 각 파라미터에서 그대로 빼줍니다(param -= step). 즉, 갱신의 부호(빼기)는 step()이 책임지고, 갱신량의 크기와 방향은 자식 클래스가 결정하는 역할 분담입니다.
  • update_dict() : NotImplementedError를 던지는 추상 메서드입니다. 자식 클래스가 반드시 재정의해야 하며, 바로 이 부분이 각 옵티마이저를 구분 짓는 본질입니다.
  • grad_norm : 갱신량의 절댓값 총합으로, 그래디언트 클리핑이나 학습 모니터링에 활용할 수 있는 부가 정보입니다(이번 실습에서는 반환만 하고 사용하지 않습니다).

이제 이 추상 클래스를 상속받아 update_dict만 채워 넣으면, 각 옵티마이저가 완성됩니다.

2. 확률적 경사 하강법 (Stochastic gradient descent)

2.1. 동기와 수식

가장 단순한 갱신 규칙인 확률적 경사 하강법(SGD) 부터 시작합니다. 손실 함수 \(\ell\)과 현재 파라미터 \(\theta_t\)가 주어졌을 때, 갱신 규칙은 다음과 같습니다.

\[ \theta_{t+1} = \theta_t - \eta\, \nabla \ell(\theta_t) \]

여기서 \(\eta\)는 학습률(learning rate) 입니다.

왜 그래디언트의 반대 방향인가. 현재 지점 \(\theta_t\) 근처에서 손실을 1차 테일러 전개하면 \[\ell(\theta_t + \Delta) \approx \ell(\theta_t) + \nabla\ell(\theta_t)^\top \Delta\] 이 됩니다. 손실을 가장 빠르게 줄이려면 \(\nabla\ell(\theta_t)^\top \Delta\)를 최소로 만드는 방향 \(\Delta\)를 골라야 하고, 크기를 고정했을 때 이 내적을 최소화하는 방향이 바로 \(-\nabla\ell(\theta_t)\)입니다(코시-슈바르츠 부등식). 즉 음의 그래디언트 방향이 국소적으로 가장 가파른 내리막이며, 그 보폭을 \(\eta\)로 조절하는 것이 SGD입니다. “확률적(stochastic)”이라는 수식어는 전체 데이터가 아닌 미니배치로 그래디언트를 근사한다는 뜻입니다.

2.2. 코드 구현

추상 클래스의 update_dict를 다음과 같이 채웁니다. 갱신량은 단순히 학습률 곱하기 (가중치 감쇠가 반영된) 그래디언트입니다.

            ############### TODO END ###########

  • 각 파라미터 키 k에 대해 갱신량을 \(\eta \cdot \nabla\ell\)로 계산합니다.
  • 이 딕셔너리가 step()에서 그대로 빼지므로, 최종 효과는 \(\theta_{t+1} = \theta_t - \eta\nabla\ell\)이 되어 수식과 정확히 일치합니다.

3. 모멘텀 (Momentum)

3.1. SGD의 한계와 동기

SGD는 그래디언트가 0이 되는 지점에서 갱신이 멈춥니다. 문제는 그런 지점이 전역 최솟값(global optimum)이 아니라 국소 최솟값(local optimum)이나 안장점(saddle point)일 수 있다는 점입니다. 또한 좁고 가파른 골짜기에서는 진동(oscillation)이 심해 수렴이 느려집니다.

이를 완화하기 위해 물리적 직관을 빌려옵니다. 공이 비탈을 굴러 내려갈 때, 평지나 작은 웅덩이를 만나도 그동안 쌓인 운동량(속도) 덕분에 관성으로 계속 나아갑니다. 이 아이디어를 갱신 규칙에 도입한 것이 모멘텀입니다.

3.2. 수식과 유도

모멘텀은 그래디언트를 즉시 쓰는 대신, 속도(velocity) \(v_t\) 에 누적한 뒤 그 속도만큼 파라미터를 갱신합니다.

\[ \begin{align*} v_{t+1} &= \beta \cdot v_t + \eta\, \nabla \ell(\theta_t)\\ \theta_{t+1} &= \theta_t - v_{t+1} \end{align*} \]

여기서 \(\beta\)는 감쇠 계수(decay) 로, 보통 0.9나 0.99를 씁니다. \(\beta < 1\)로 두는 이유는 속도가 무한히 누적되어 발산하는 것을 막기 위함입니다.

속도 항이 실제로 무엇을 의미하는지, 초기값 \(v_0 = 0\)에서 재귀식을 풀어 봅니다.

\[ \begin{align*} v_1 &= \eta\, \nabla\ell(\theta_0)\\ v_2 &= \beta v_1 + \eta\,\nabla\ell(\theta_1) = \beta\eta\,\nabla\ell(\theta_0) + \eta\,\nabla\ell(\theta_1)\\ v_3 &= \beta v_2 + \eta\,\nabla\ell(\theta_2) = \beta^2\eta\,\nabla\ell(\theta_0) + \beta\eta\,\nabla\ell(\theta_1) + \eta\,\nabla\ell(\theta_2) \end{align*} \]

일반항으로 정리하면 다음과 같습니다.

\[ v_{t+1} = \eta \sum_{k=0}^{t} \beta^{\,t-k}\, \nabla \ell(\theta_k) \]

즉 속도는 과거 그래디언트들의 지수 가중 합(exponentially weighted sum) 입니다. 가까운 과거일수록 가중치가 크고, 먼 과거는 \(\beta^{t-k}\)로 빠르게 잊힙니다.

발산하지 않는 이유. 만약 그래디언트의 크기가 대략 일정한 상수 \(g\)라고 가정하면, 속도의 크기는 등비급수의 합으로 수렴합니다. \[\eta \sum_{k=0}^{t}\beta^{\,t-k} g \le \eta g \sum_{i=0}^{\infty}\beta^{i} = \frac{\eta g}{1-\beta}\] 예컨대 \(\beta = 0.9\)이면 최대 보폭이 SGD의 약 \(\frac{1}{1-0.9}=10\)배까지 커질 수 있습니다. 일관된 방향의 그래디언트는 누적되어 가속되고, 방향이 들쭉날쭉한 성분은 서로 상쇄되어 진동이 억제됩니다.

3.3. 코드 구현

속도를 스텝 간에 기억해야 하므로, 파라미터 딕셔너리와 동일한 구조의 momentum_dict를 0으로 초기화해 보관합니다.

4. RMSProp

4.1. 동기: 학습률을 적응적으로 조절하기

모멘텀까지 와도 학습률 \(\eta\)는 여전히 모든 파라미터에 동일하게 적용되는 단일 상수입니다. 그러나 파라미터마다 손실에 대한 민감도(sensitivity)는 제각각입니다. 어떤 가중치는 조금만 움직여도 손실이 크게 출렁이고, 어떤 가중치는 크게 움직여야 변화가 생깁니다. 모든 파라미터에 같은 학습률을 쓰면, 민감한 방향에서는 발산하고 둔감한 방향에서는 지나치게 느려지는 문제가 생깁니다.

RMSProp의 아이디어는 다음과 같습니다.

그래디언트가 컸던(민감한) 파라미터에는 작은 학습률을, 그래디언트가 작았던(둔감한) 파라미터에는 큰 학습률을 부여하자.

4.2. 수식과 유도

각 파라미터의 민감도를 그래디언트 제곱의 지수 이동 평균(EMA) \(G_t\)로 추정하고, 갱신량을 \(\sqrt{G_t}\)로 나눠 줍니다.

\[ \begin{align*} G_{t+1} &= \beta\, G_t + (1-\beta)\, (\nabla \ell(\theta_t))^2\\ \theta_{t+1} &= \theta_t - \frac{\eta}{\sqrt{G_{t+1}} + \epsilon} \cdot \nabla \ell(\theta_t) \end{align*} \]

여기서 제곱 \((\nabla\ell)^2\)과 나눗셈은 모두 원소별(element-wise) 연산입니다. 즉 파라미터의 각 성분이 자기만의 분모를 갖게 되어, 실질적으로 파라미터별로 다른 학습률이 적용됩니다.

  • \(G_t\)의 의미. \(G_{t+1} = \beta G_t + (1-\beta)(\nabla\ell)^2\)는 그래디언트 제곱의 EMA입니다. 가중치 \(\beta\)와 \(1-\beta\)의 합이 1이므로, \(G_t\)는 최근 그래디언트 제곱의 “평균적 크기”를 추적합니다. 이름 그대로 제곱(Square)의 평균(Mean)을 취한 뒤 제곱근(Root)을 씌워 나누므로 RMS(Root Mean Square)Prop입니다.
  • \(\epsilon\)의 역할. \(G_{t+1}\)이 0에 가까운 둔감한 파라미터에서 분모가 0이 되어 갱신량이 폭발하는 것을 막는 수치 안정화 항입니다(코드에서 1e-6).
  • 적응적 학습률. 그래디언트가 크게 누적된 방향은 \(\sqrt{G_{t+1}}\)가 커져 보폭이 자동으로 줄고, 반대로 둔감한 방향은 보폭이 상대적으로 커집니다. 결과적으로 모든 방향의 갱신 크기가 비슷하게 정규화됩니다.

4.3. 코드 구현

class RMSProp(Optimizer):
    def __init__(self, model, lr=0.01, beta=0.9, wd=0.001, **kwargs):
        super(RMSProp, self).__init__(model, **kwargs)
        self.lr = lr
        self.beta = beta
        self.eps = 1e-6
        self.G_dict = {k: torch.zeros_like(v) for k, v in self.param_dict.items()}

    def update_dict(self):
        grad_dict = unfold_dict(self.model.grad_dict())
        grad_dict = self.wd_grad(grad_dict)
        step_dict = {}
        for k in self.param_dict.keys():
            ############### TODO ###############
            self.G_dict[k] = self.beta * self.G_dict[k] + (1 - self.beta) * grad_dict[k] ** 2
            step_dict[k] = self.lr * grad_dict[k] / (torch.sqrt(self.G_dict[k]) + self.eps)
            ############### TODO END ###########

        return step_dict
  • self.G_dict[k]가 \(G_t\)이며, 첫 줄에서 \(G_{t+1}\)로 갱신됩니다.
  • step_dict[k]는 \(\dfrac{\eta}{\sqrt{G_{t+1}}+\epsilon}\nabla\ell\)로, step()에서 빼지면 수식과 일치합니다.
  • 모멘텀과 마찬가지로 G_dict라는 내부 상태를 유지하되, 누적하는 대상이 그래디언트 자체가 아니라 그래디언트 제곱이라는 점이 다릅니다.

5. Adam

5.1. 동기: 두 마리 토끼를 모두

지금까지의 발전을 정리하면 두 갈래입니다.

  • Momentum : 과거 그래디언트를 누적해 갱신 방향을 안정화 (1차 모멘트)
  • RMSProp : 그래디언트 제곱을 추적해 갱신 크기를 적응적으로 조절 (2차 모멘트)

Adam(Adaptive Moment Estimation) 은 이 둘을 결합합니다. 직관은 다음과 같습니다.

  • \(m_t\) (1차 모멘트) : 파라미터의 모멘텀을 나타냅니다. 일관된 갱신 방향을 가진 파라미터는 갱신이 장려됩니다.
  • \(v_t\) (2차 모멘트) : 파라미터의 민감도를 나타냅니다. 갱신이 컸던 파라미터는 갱신이 억제됩니다.
  • 최종 갱신량은 \(m_t\)와 \(v_t\)를 모두 고려합니다.

5.2. 수식과 편향 보정(bias correction) 유도

\[ \begin{align*} m_{t+1} &= \beta_1 \cdot m_t + (1 - \beta_1)\cdot \nabla \ell(\theta_t)\\ v_{t+1} &= \beta_2 \cdot v_t + (1 - \beta_2)\cdot (\nabla \ell(\theta_t))^2\\ \hat{m}_{t+1} &= m_{t+1} / (1 - \beta_1^{t})\\ \hat{v}_{t+1} &= v_{t+1} / (1 - \beta_2^{t})\\ \theta_{t+1} &= \theta_t - \eta \cdot \frac{\hat{m}_{t+1}}{\sqrt{\hat{v}_{t+1}} + \epsilon} \end{align*} \]

앞의 두 식(\(m, v\))은 각각 모멘텀과 RMSProp의 EMA와 본질적으로 같습니다. 새로 등장한 것은 편향 보정 단계인 \(\hat m, \hat v\)입니다. 왜 \(1-\beta^t\)로 나눠 줄까요?

문제는 \(m_0 = 0,\, v_0 = 0\)으로 초기화한다는 점입니다. 이 0이라는 초기값이 학습 초기에 모멘트 추정치를 0 쪽으로 끌어내리는 편향을 만듭니다. 이를 정량적으로 보겠습니다. \(m_t\)를 풀어쓰면(섹션 3의 전개와 동일한 방식),

\[ m_{t} = (1-\beta_1)\sum_{k=1}^{t}\beta_1^{\,t-k}\, \nabla\ell(\theta_k) \]

이제 그래디언트의 기댓값이 대략 일정한 값 \(\mathbb{E}[g]\)라고 가정하고 양변에 기댓값을 취하면, \(\mathbb{E}[\nabla\ell(\theta_k)] \approx \mathbb{E}[g]\)를 합 밖으로 빼낼 수 있습니다.

\[ \mathbb{E}[m_t] \approx \mathbb{E}[g] \cdot (1-\beta_1)\sum_{k=1}^{t}\beta_1^{\,t-k} \]

등비급수의 합 공식 \(\sum_{k=1}^{t}\beta_1^{\,t-k} = \sum_{j=0}^{t-1}\beta_1^{\,j} = \dfrac{1-\beta_1^{t}}{1-\beta_1}\)을 대입하면,

\[ \mathbb{E}[m_t] \approx \mathbb{E}[g]\,(1-\beta_1)\cdot\frac{1-\beta_1^{t}}{1-\beta_1} = \mathbb{E}[g]\,(1-\beta_1^{t}) \]

즉 \(m_t\)의 기댓값은 우리가 추정하고 싶은 \(\mathbb{E}[g]\)에 비해 \((1-\beta_1^t)\)배만큼 과소 추정되어 있습니다. 따라서 이 인자로 다시 나눠 주면 편향이 제거됩니다.

\[ \mathbb{E}[\hat m_t] = \frac{\mathbb{E}[m_t]}{1-\beta_1^{t}} \approx \mathbb{E}[g] \]

\(\hat v_t\)도 동일한 논리로 보정됩니다.

왜 초반에만 중요한가. \(t\)가 커지면 \(\beta_1^t \to 0\)이므로 보정 인자 \(1-\beta_1^t \to 1\)이 되어, 편향 보정의 효과는 사실상 사라집니다. 즉 이 보정은 학습 초기 몇 스텝에서 모멘트 추정이 0으로 쪼그라드는 현상을 막아 주는 장치입니다. 이 덕분에 Adam은 초기부터 안정적이고 빠른 학습이 가능합니다.

5.3. 코드 구현

class Adam(Optimizer):
    def __init__(self, model, lr=0.01, beta1=0.9, beta2=0.9, wd=0.001, **kwargs):
        super(Adam, self).__init__(model, **kwargs)
        self.lr = lr
        self.beta1 = beta1
        self.beta2 = beta2
        self.eps = 1e-6
        self.m_dict = {k: torch.zeros_like(v) for k, v in self.param_dict.items()}
        self.v_dict = {k: torch.zeros_like(v) for k, v in self.param_dict.items()}
        self.t = 1

    def update_dict(self):
        grad_dict = unfold_dict(self.model.grad_dict())
        grad_dict = self.wd_grad(grad_dict)
        step_dict = {}
        for k in self.param_dict.keys():
            ############### TODO ###############
            self.m_dict[k] = self.beta1 * self.m_dict[k] + (1 - self.beta1) * grad_dict[k]
            self.v_dict[k] = self.beta2 * self.v_dict[k] + (1 - self.beta2) * grad_dict[k] ** 2
            m_hat = self.m_dict[k] / (1 - self.beta1 ** self.t)
            v_hat = self.v_dict[k] / (1 - self.beta2 ** self.t)
            step_dict[k] = self.lr * m_hat / (torch.sqrt(v_hat) + self.eps)
            ############### TODO END ###########
        self.t += 1

        return step_dict

구현상 짚어 둘 점은 다음과 같습니다.

  • 상태가 두 개입니다. 1차 모멘트 m_dict와 2차 모멘트 v_dict를 모두 0으로 초기화해 유지합니다. Momentum과 RMSProp의 상태를 한 옵티마이저에 합친 셈입니다.
  • 스텝 카운터 self.t 가 필수입니다. 편향 보정 항 \(1-\beta^t\)가 \(t\)에 의존하므로, 매 update_dict 호출 끝에서 self.t += 1로 증가시킵니다. t=1에서 시작하는 점에 유의하세요.
  • 이 실습 코드에서는 beta2=0.9로 설정되어 있습니다. 원논문의 권장값(\(\beta_2 = 0.999\))과는 다른데, 본 실습의 짧은 학습(50 epoch)에 맞춘 선택으로 보입니다. 일반적인 실무에서는 \(\beta_1=0.9,\ \beta_2=0.999\) 조합이 표준입니다.

6. Transformer 학습 (Transformer training)

6.1. 실험 설계

이제 직접 만든 네 옵티마이저로 Transformer 언어 모델을 실제로 학습시켜 성능을 비교합니다. 데이터는 셰익스피어 텍스트(Shakespeare)이며, 모델은 바이트 단위 토큰을 다루는 작은 Transformer입니다.

import torch
from model import Transformer
from util import Shakespeare

vocab_size = 256 + 256
device = 'cuda:0'
shakespeare = Shakespeare(device, vocab_size)
  • vocab_size = 256 + 256 : 기본 바이트(256개)에 특수 토큰 공간을 더한 어휘 크기입니다.
  • Shakespeare 객체가 학습/평가용 데이터로더와 데이터셋 크기 정보를 제공합니다.

6.2. 학습 루프

네 옵티마이저를 딕셔너리로 모아 두고, 동일한 조건에서 각각 새 모델을 학습시킵니다.

batch_size, seq_len, lr = 64, 100, 0.03

optimizers = {
    'SGD': SGD,
    'Momentum': Momentum,
    'RMSProp': RMSProp,
    'Adam': Adam,
}

train_log = {'SGD': [], 'Momentum': [], 'RMSProp': [], 'Adam': []}
test_log  = {'SGD': [], 'Momentum': [], 'RMSProp': [], 'Adam': []}

for name, opt_class in optimizers.items():
    model = Transformer(4, vocab_size, 128, 16).to(device)
    optimizer = opt_class(model, lr=lr, wd=0.001)

    print(f"Optimizer: {name}")

    for i in range(50):
        train_loss, test_loss = 0, 0

        for input_idx, label in shakespeare.dataloader('train', batch_size, seq_len):
            logits, loss = model(input_idx, label)
            model.backward(torch.zeros_like(logits), torch.ones_like(loss))
            optimizer.step()

            pred = torch.argmax(logits, dim=-1)
            train_loss += loss.item() * label.numel()

        for input_idx, label in shakespeare.dataloader('test', batch_size, seq_len):
            logits, loss = model(input_idx, label)

            pred = torch.argmax(logits, dim=-1)
            test_loss += loss.item() * label.numel()

        train_loss = train_loss / shakespeare.trainset_size
        test_loss = test_loss / shakespeare.testset_size

        if i % 10 == 0:
            print(f"[{i:3d}/50], train loss {train_loss:.4f}, test loss {test_loss:.4f}")

        train_log[name].append(train_loss)
        test_log[name].append(test_loss)
    print()

학습 루프의 핵심 절차는 다음과 같습니다.

  • 공정한 비교를 위해 옵티마이저마다 Transformer를 새로 초기화합니다. 모든 옵티마이저가 동일한 모델 구조(Transformer(4, vocab_size, 128, 16): 4개 층, 임베딩 차원 128, 헤드 16개로 해석)에서 같은 출발선에 섭니다.
  • 순전파(logits, loss = model(input_idx, label))로 손실을 구하고, 역전파(model.backward(...))로 그래디언트를 채운 뒤, optimizer.step() 으로 파라미터를 갱신합니다. 바로 이 한 줄이 우리가 구현한 갱신 규칙을 호출하는 지점입니다.
  • 손실은 토큰 수(label.numel())로 가중해 누적한 뒤 전체 데이터셋 크기로 나눠, 토큰당 평균 손실로 정규화합니다.
  • 매 epoch의 학습/평가 손실을 train_log, test_log에 기록해 이후 비교에 사용합니다.

마무리 (Summary)

이번 실습에서는 옵티마이저를 밑바닥부터 구현하며, 갱신 규칙이 어떻게 점진적으로 정교해지는지를 따라왔습니다.

  • 추상 클래스 : 공통 골격(step, wd_grad)은 부모에, 갱신 규칙(update_dict)은 자식에 두는 설계로 코드 중복을 제거했습니다.
  • SGD : 가장 가파른 내리막 방향으로 한 걸음씩. 단순하지만 정체·진동에 취약합니다.
  • Momentum : 과거 그래디언트를 지수 가중 합으로 누적해 관성을 부여, 진동을 줄이고 평탄 구간을 가속합니다.
  • RMSProp : 그래디언트 제곱의 EMA로 파라미터별 민감도를 추정해 학습률을 적응적으로 조절합니다.
  • Adam : 1차·2차 모멘트를 모두 추적하고 편향 보정까지 더해, 모멘텀과 적응적 학습률의 장점을 결합합니다.

각 방법의 한계가 다음 방법의 동기가 되는 구조를 이해하셨다면, 새로운 옵티마이저(예: AdamW, Nadam)를 마주쳤을 때도 “기존 무엇을 어떻게 보완했는가”라는 질문으로 빠르게 파악하실 수 있을 것입니다.
