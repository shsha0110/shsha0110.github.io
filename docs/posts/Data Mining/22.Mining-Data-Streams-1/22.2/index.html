1. 스트림 샘플링의 필요성과 두 가지 접근법

  • 이전 포스트에서 살펴보았듯, 데이터 스트림 환경의 가장 큰 난관은 전체 데이터를 메인 메모리에 저장할 수 없다는 점입니다. 하지만 전체 데이터를 다루지 않더라도, 원본 데이터의 특성을 잘 반영하는 ’좋은 표본(Good sample)’을 추출할 수 있다면 매우 효율적인 근사 알고리즘을 설계할 수 있습니다.

  • 무한히 유입되는 데이터 스트림에서 샘플을 추출하는 방법은 크게 두 가지 접근법으로 나뉩니다:

      1. 고정 비율 샘플링 (Fixed Proportion Sampling): 스트림으로 들어오는 요소 중 일정한 비율(예: 10%)을 무작위로 추출하는 방식입니다.
      1. 고정 크기 샘플링 (Fixed-Size Sampling): 무한한 스트림 전체에 걸쳐 항상 고정된 크기(Size)의 무작위 표본을 유지하는 방식입니다.

2. 고정 비율 샘플링 (Sampling a Fixed Proportion)

  • 첫 번째 접근법은 들어오는 데이터 요소에 대해 특정한 고정 비율(예: 10%)을 샘플링하는 것입니다.

  • 가장 단순한 형태의 알고리즘(Naïve algorithm)은 다음과 같습니다. 데이터 요소가 하나 들어올 때마다 0부터 9 사이의 무작위 정수를 생성합니다. 만약 난수가 0이면 해당 요소를 메모리에 저장하고, 그렇지 않으면 즉각 폐기(Discard)합니다.

  • 하지만 이 단순 무작위 접근법은 스트림 환경에서 치명적인 한계점 두 가지를 가집니다:

      1. 데이터 스트림이 무한히 유입됨에 따라 샘플의 크기 또한 무한히 커져 결국 메모리를 초과하게 됩니다.
      1. 특정 애플리케이션에서는 모집단에 대한 완전히 잘못된 추정치(Wrong estimate)를 도출하게 됩니다.

2.1. 단순 무작위 샘플링의 치명적 한계: 검색어 중복 비율 추정

  • 두 번째 한계점인 ’잘못된 추정치 도출’이 어떻게 발생하는지 직관적인 예시를 통해 증명해 보겠습니다. 검색 엔진에 유입되는 질의어(Query) 스트림을 분석하여, “전체 질의어 중 중복해서 발생한 질의어의 비율은 얼마인가?”를 추정한다고 가정해 봅시다.

  • 데이터는 (사용자, 검색어, 시간) 형태의 튜플로 들어옵니다. 분석의 편의를 위해 전체 스트림이 다음과 같이 구성되어 있다고 가정합니다:

    • 한 번만 검색된 고유 질의어의 개수: \(x\) 개
    • 정확히 두 번씩 검색된 중복 질의어의 개수: \(d\) 개

  • 이 경우 전체 스트림에 등장한 총 질의어 인스턴스의 수는 \(x + 2d\) 가 되며 , 전체 고유 질의어 종류(\(x + d\)) 중 중복 질의어가 차지하는 실제 정답(Ground Truth) 비율은 \(\frac{d}{x+d}\) 입니다.

2.2. 수식 증명: Uniform Sampling의 과소추정 (Underestimation) 문제

  • 단순 무작위 방식으로 전체 스트림 요소의 10%를 샘플링했을 때, 위 비율을 어떻게 추정하게 되는지 수학적으로 계산해 봅시다.
  • 다이어그램의 흐름을 따라 표본 내 질의어들의 상태를 수식으로 정리하면 다음과 같습니다.
      1. 1회 발생 질의어 (\(x\)): 표본 추출 확률이 \(1/10\)이므로, 샘플 내에는 \(\frac{x}{10}\) 개의 질의어가 남습니다.
      1. 2회 발생 질의어 (\(d\)): 각 인스턴스가 독립적으로 샘플링 과정을 거치므로 두 가지 케이스로 분화됩니다.
      • 두 번 모두 샘플에 포함될 확률: \(\frac{1}{10} \times \frac{1}{10} = \frac{1}{100}\). 따라서 원래 중복 질의어 중 표본 내에서도 ’중복(Twice)’으로 올바르게 관측되는 개수는 \(d \left(\frac{1}{10} \times \frac{1}{10}\right) = \frac{d}{100}\) 개뿐입니다.
      • 두 번 중 한 번만 샘플에 포함될 확률: 독립 시행의 확률에 따라 \(2 \times \frac{1}{10} \times \frac{9}{10} = \frac{18}{100}\) 이 됩니다. 즉, 표본 내에서 한 번만 관측되어 ’고유 질의어(Once)’로 오인되는 개수는 \(d \left(2 \times \frac{1}{10} \times \frac{9}{10}\right) = \frac{18d}{100}\) 개에 달합니다.
  • 결과적으로 다이어그램 하단과 같이 10% 샘플 데이터만을 가지고 중복 질의어의 비율을 계산하면 다음과 같은 수식이 도출됩니다:

\[\text{Fraction of repeated queries} = \frac{d/100}{x/10 + d/100 + 18d/100} = \frac{d}{10x + 19d}\]

  • 이 결과값 \(\frac{d}{10x + 19d}\)는 실제 정답인 \(\frac{d}{x+d}\) 보다 훨씬 작은 값입니다. 즉, 균등 샘플링(Uniform sampling)은 이처럼 특정 요소가 묶음으로 나타나는 빈도 데이터를 분석할 때 통계치를 심각하게 과소추정(Underestimates)하게 만듭니다.

2.3. 해결책: 키 기반의 사용자 샘플링 (Sample Users, Not Queries)

  • 이러한 통계적 왜곡을 방지하기 위한 해결책은 개별 쿼리 요소 단위가 아니라, 튜플의 특정 키(Key)를 기준으로 샘플링하는 것입니다.

  • 위 예제에서는 쿼리 자체가 아니라 ’사용자(User)’를 샘플링해야 합니다. 전체 사용자의 1/10을 무작위로 선택하고, 선택된 사용자가 발생시킨 모든 검색 쿼리를 샘플에 포함시키는 방식입니다. 이를 구현하기 위해 사용자 ID나 이름을 키로 사용하여 10개의 버킷(Buckets)을 가진 해시 함수(Hash function)를 적용합니다. 해시 함수가 사용자를 균등하게 분포시킨다고 가정하면(Uniformly distributes), 모집단의 특성을 왜곡 없이 유지하는 10%의 표본을 추출할 수 있습니다.

  • 물론 이 방식에도 한계는 존재합니다. 어떤 키(사용자)들은 시스템 내에서 영원히 샘플링되지 않을 수 있으며, 만약 그 사용자가 통계적으로 매우 중요한(Important) 이상치나 핵심 유저라면 문제가 될 수 있습니다. 따라서 해결하려는 목적에 맞게 ’이것이 과연 좋은 샘플링인가?’에 대한 고민이 선행되어야 합니다.

3. 고정 크기 샘플링과 저수지 샘플링 (Reservoir Sampling)

  • 비율 기반 샘플링의 또 다른 본질적 한계는 메모리 초과 문제였습니다. 스트림 데이터는 그 길이를 사전에 알 수 없고, 우리의 메인 저장소(Main storage) 크기는 한정되어 있기 때문에, 고정 비율로 샘플링하더라도 데이터가 무한히 누적되면 결국 저장 공간이 고갈(Run out of storage)됩니다.

  • 따라서 현실적인 스트림 시스템에서는 두 번째 접근법인 고정 크기 샘플링(Maintaining a Fixed-Size Sample)을 사용해야 합니다.

  • 우리의 최종 목표는 지금까지 관측한 총 데이터 개수 \(n\)이 얼마가 되든, 크기가 \(s\) (\(s = |S|\))인 표본 집합 \(S\) 내에 각 원소가 포함되어 있을 확률이 항상 \(s/n\)로 동일하게 유지되도록 하는 것입니다.

  • 예를 들어, 표본 크기 \(s=2\)일 때 \(a, x, c, y, z \dots\) 순서로 들어오는 스트림을 가정해 보겠습니다.

    • \(n=5\) 시점 (총 5개 관측): 현재 메모리 집합이 \(S={a,c}\)라고 할 때, 각 요소가 샘플로 선택되어 있을 확률은 동일하게 \(2/5\)여야 합니다.
    • \(n=7\) 시점 (총 7개 관측): 과거에 들어왔던 요소들의 샘플 잔류 확률은 기존 \(2/5\)에서 줄어들어 모두 \(2/7\)이 되어야 하며, 새롭게 유입된 요소들 역시 정확히 \(2/7\)의 확률로 메모리에 진입할 기회를 가져야 합니다.

3.1. 저수지 샘플링 (Reservoir Sampling) 알고리즘

  • 이를 완벽하게 구현하는 매우 효과적인 스트림 알고리즘이 바로 저수지 샘플링(Reservoir Sampling)입니다. 알고리즘의 동작 단계는 놀라울 정도로 단순합니다.
    • Step 1: 스트림으로 들어오는 최초의 \(s\)개 원소들은 아무 조건 없이 모두 메모리 \(S\)에 저장합니다.
    • Step 2: 메모리가 꽉 찬 이후, 즉 \(n\)번째 요소가 도착했을 때 (\(n > s\)):
        1. 새로 도착한 \(n\)번째 요소를 \(s/n\)의 확률로 메모리 유지 대상에 선정하고, 선택되지 않았다면 폐기(Discard)합니다.
        1. 만약 새 요소를 선택했다면, 기존 메모리 집합 \(S\)에 있던 \(s\)개의 원소 중 하나를 무작위로 선택하여 새로운 요소와 교체(Replace)합니다. 새 요소를 선택하지 않았다면 아무 작업도 하지 않습니다 (Do nothing).

4. 저수지 샘플링의 수학적 증명 (Proof by Induction)

  • 이 단순한 알고리즘이 정말로 ” \(n\)개의 요소를 본 후, \(S\)는 각 요소를 정확히 \(s/n\)의 확률로 포함한다”는 속성을 완벽히 유지하는지 수학적 귀납법(Proof by induction)을 통해 증명해보겠습니다.
  • 기저 사례 (Base case: \(n=s\)):
    • 최초의 \(s\)개 요소는 모두 무조건 저장되므로 샘플에 포함될 확률은 \(s/s = 1\)이 되어 속성을 만족합니다.
  • 귀납적 가정 (Inductive step assumption):
    • \(n\)개의 원소가 지나간 시점에서, 특정 원소가 메모리 집합 \(S\)에 포함되어 있을 확률이 정확히 \(\frac{s}{n}\) 이라고 가정합니다.
  • 증명 (Show property holds for \(n+1\)):
    • 이제 \(n+1\) 번째 새로운 원소가 유입되었을 때, 모든 원소들이 메모리에 존재할 확률이 \(\frac{s}{n+1}\) 로 갱신됨을 보이면 됩니다.
    • 새로 들어온 원소(\(n+1\))는 알고리즘 규칙에 따라 정확히 \(\frac{s}{n+1}\) 의 확률로 집합 \(S\)에 들어갑니다.
    • 그렇다면 원래 메모리 집합 \(S\)에 존재하던 임의의 원소 \(v\)가 \(n+1\) 단계가 끝난 후에도 쫓겨나지 않고 집합 \(S\)에 잔류(Remain)할 확률은 얼마일까요? 이 확률은 다음과 같이 구성됩니다. \[P(v \text{ 가 잔류}) = P(v \text{ 가 } n \text{ 시점까지 } S \text{ 에 존재함}) \times P(v \text{ 가 새 원소에 의해 교체되지 않음})\]
    • \(v\)가 교체되지 않을 확률은 두 가지 상호 배타적 사건의 합입니다.
        1. 새 원소가 아예 선택되지 않을 확률.
        1. 새 원소가 선택되었으나, 메모리 교체 대상 \(s\)개 중 \(v\)가 아닌 다른 원소가 방출될 확률.
    • 이를 수식으로 풀어쓰면 다음과 같습니다: \[P(v \text{ 가 교체되지 않음}) = \underbrace{\left( 1 - \frac{s}{n+1} \right)}_{\text{Term 2: 새 원소 미선택}} + \underbrace{\left( \frac{s}{n+1} \right) \cdot \left( \frac{s-1}{s} \right)}_{\text{Term 3: 새 원소 선택, } v \text{ 는 미교체}}\]
    • 괄호 안을 정리하면, \[\left( 1 - \frac{s}{n+1} \right) + \frac{s-1}{n+1} = \frac{n+1-s + s-1}{n+1} = \frac{n}{n+1}\]
    • 이제 전체 잔류 확률을 계산하기 위해 귀납적 가정(Term 1: \(n\) 시점까지 \(v\)가 존재할 확률 \(\frac{s}{n}\))을 곱해줍니다: \[\frac{s}{n} \cdot \left[ \frac{n}{n+1} \right] = \frac{s}{n+1}\]
    • 증명이 완료되었습니다. 유입되는 원소의 수 \(n\)이 아무리 커져도, 메모리 내의 모든 원소는 동일하게 \(\frac{s}{n}\)의 확률을 무한히 보장받습니다. 이것이 저수지 샘플링이 메모리 제한 환경에서 수학적으로 완벽하게 기능하는 이유입니다.
